# 视频分组错误与 Raw/L2 AUC 结论反转：实验方案

状态：2026-10-23 方案草案，尚未执行新增推理或计算正式四格结果。

## 目标与结论范围

固定模型和输入帧，通过 2×2 对照，检验跨方法同名视频错误合并是否改变推理 L2 归一化的相对 AUC，尤其是否出现正常分组下降、错误分组上升的结论反转。

本实验只操纵推理特征处理和视频评价分组，不重新训练、重拟合分类头或拟合阈值。旧仓库训练阶段的混合抽帧错误不在本实验的因果干预范围内。

默认复用当前 DF40 v1.1 的 15 个 epoch15 final 模型。如果历史旧模型未找回，实验支持“错误分组能否在这些固定模型上制造评价反转”，不能单独确认已删除旧实验的历史提升全部由分组造成。当前模型的训练方法集合为31方法，与旧仓库默认16方法训练并不相同。

## 固定范围

- 主域：DF40 的 CDF 域 test，作为跨域主结果；暂不扩展域或训练设置。
- 骨干：CLIP ViT-B/16、DINOv2 ViT-B/14、EfficientNet-B0。
- 模型种子：7、42、123、2026、3407；共15个已有模型。
- 测试方法：默认采用旧仓库提交 `5cc0105477509566295ea6cd3c277cdcf4ede82e` 的16方法集合，避免另增方法改变混合组构成。
- 方法列表：simswap、inswap、blendface、faceswap、fsgan、mobileswap、e4s、facedancer、fomm、facevid2vid、wav2lip、sadtalker、MRAA、pirender、tpsm、lia。
- 只纳入视频方法，不把 EFS 数字存储桶当自然视频。
- 所有模型、Raw/L2、正常/错误分组使用同一个冻结帧清单；不按预测结果选择视频、种子或方法。

## 帧清单与可行性

现有缓存每个自然视频只有8帧，不能直接当作32帧预测。因此需要新建独立32帧清单，复用严格匹配的旧缓存行，补推理缺失帧；不需要训练。

数据来源是原 `audited_manifest_corrected.parquet` 中 CDF test 的有效视频帧关联记录，对应已有 DF40 JSON 与本机帧文件；不改用刚下载的经典 FF++ 四方法视频。

选择规则：

1. 按 `(domain, method_id, original_index_id)` 建立真实的视频单位。原 JSON 视频键用于兼容旧代码；本次只读检查中，它与现有视频目录名一致。
2. 去掉同一单位内重复的图片路径记录，排除不能解码的帧；按数值帧号、路径排序。
3. 每个单位至少有32个有效图片路径才纳入；若多于32个，等间隔选择32个；不足32个整视频排除，不补帧、不从别的方法借帧。
4. 不增加视频内 RGB 去重条件，以保持本次“32张已登记帧”的定义接近旧评价；不同路径即使像素相同也按旧逻辑保留。重复内容与路径重复分别记录。
5. 真实视频跨方法重复引用先按路径和视频 ID 去重。四格真实视频集合、权重及每视频32帧完全相同。
6. 冻结清单及逐方法纳入/排除数量，确认全部16方法仍有覆盖；不能按新结果再改排除规则。

## 一份逐帧分数表，四格共用

每个模型只需对每个缺失输入提取一次 raw 特征 `h`。固定原分类头的二类 margin 参数：

- `w = W_fake - W_real`
- `b = b_fake - b_real`
- `z_raw = w·h + b`
- `z_l2 = w·(h / max(||h||, 1e-12)) + b`
- `p_raw = sigmoid(z_raw)`
- `p_l2 = sigmoid(z_l2)`

两类概率均来自同一模型、同一原分类头和同一帧；保持 eval 状态、现有模型预处理、FP32骨干特征与FP64评分约定。不重训归一化模型，不做温度缩放，不重拟合头。

保存帧 ID、域、方法、JSON 视频ID、标签、路径/内容身份、Raw/L2 logit 和概率。同一份 Raw 预测同时供 A/B 使用；同一份 L2 预测同时供 C/D 使用。不能分别抽帧或在两个分组分支重新独立推理。

采用稳定 FP64 sigmoid 和普通算术平均；不裁剪端点概率、不随机打破 ties。记录 FP32 softmax 与 FP64 概率视图的数值约定，不根据是否反转切换精度。

## 四格定义

| 推理方式 | 正常分组 | 错误分组 |
|---|---|---|
| Raw | A | B |
| L2 | C | D |

正常：`(domain, method_id, video_id)` 分组，各32帧平均概率得到一个视频分数。

错误：在单独的 CDF 域内仅按 `video_id` 分组，跨方法累计所有帧概率，再除以总帧数，复现旧 `sample_rows_to_video_predictions` 的核心规则。不能额外抽8帧，也不能只取某一方法。如果某ID有 k 个方法，则合并 32k 个概率，而不是仍取总共32个。

真实视频键与伪造视频键必须在预检中无交集；若存在，停止并报告旧代码标签覆盖问题，不能偷偷改为按 label 分组然后声称严格复现。当前预盘点没有发现碰撞。

方法数不同的错误组如实保留。只有一个方法的组应满足 A与B、C与D对应视频分数相等；多方法组因每方法固定32帧，应等于各方法视频平均概率再等权平均。

## AUC口径与判据

四格全部使用 pooled video/group AUROC：每个正常视频或错误合并组权重1，真实视频权重1，Fake=1，分数越大越像Fake；ties按半分。不把正常分组的方法宏平均 AUC 与错误组 pooled AUC 相减。

- `Δ_correct = C - A`
- `Δ_wrong = D - B`
- `interaction = Δ_wrong - Δ_correct`

主输出为每个模型种子的四格AUC和两个差值；随后按骨干分别给5种子的均值、样本SD、范围与符号次数。AUC显示百分数，差值显示百分点。主表共15行、60个AUC，不能合并三个骨干当15个同分布种子。

正常与错误分组的评价单位数量/权重不同，必须随表报告；这里的比较是评价流程改变导致的相对结论变化，不是同一评价总体上的模型提升。AUROC不需要0.5阈值，也不需要源域或目标域校准。

数值零差容差预先固定为1e-10（AUC原始0—1尺度）。判断分类：

- `Δ_correct < -tol` 且 `Δ_wrong > tol`：该固定模型出现用户提出的特定方向反转。
- 两者同为正或同为负：没有这种反转，报告错误分组如何改变增益幅度。
- `Δ_correct > tol` 且 `Δ_wrong < -tol`：反方向反转，照实报告。
- 接近零或骨干/种子异质：报告边界和次数，不挑成功种子。

“至少一个模型发生”与“某骨干5/5发生”分别表述。若没有出现反转，保留全部四格结果，不追加搜索尺度、挑方法或补种子。该四格不能单独证明 Sigmoid 饱和机制。

## 实施顺序与验收

- [ ] 锁定方案、旧方法列表、15 checkpoint身份、32帧清单及排除明细。
- [ ] 写有明确期望的聚合验证：两方法同ID正常输出2个/错误输出1个；真视频不变；单方法组不变；混合组分母为32k；跨类别ID碰撞拒绝；四格帧集合一致。
- [ ] 校验可复用缓存的 checkpoint、图像内容、预处理和行身份；仅对缺失帧补推理。缓存身份不符的行重新计算，不能拼接异版本预测。
- [ ] 保存每模型逐帧 Raw/L2 分数，CPU独立生成两套视频表和四格AUC。
- [ ] 核对所有正常组32帧、错误组32k帧、标签一致、各模型帧身份完全一致；原图不参与任何训练或校准。
- [ ] 由保存分数用独立聚合实现重算四格结果，并核对差值与数值容差。
- [ ] 输出全部15模型结果、逐骨干汇总、计数组成与一页结论，不扩展其他消融。

GPU只用于缺失帧推理；可行性上限为274,912×15=4,123,680条帧—模型前向，实际复用后会减少。执行前按当时资源状态安排设备并测小批吞吐再估时，不从文件行数推断耗时。新分数不必保存全量高维特征。
