# Final Experiment Results

This directory contains the concise result set for the retained experiments.

## Model Set

There are 30 trained models:

- 3 backbones: CLIP, DINOv2, EfficientNet
- 5 seeds: 7, 42, 123, 999, 2048
- 2 training modes: raw train and norm train

Each backbone has 10 checkpoints: 5 raw-train models and 5 norm-train models.

## Files

- `auc_video_level_60rows.csv`: video-level AUC results.
  - 60 rows = 3 backbones x 5 seeds x 4 evaluated modes.
  - Raw-train models have `raw`, `direction`, and `length` inference rows.
  - Norm-train models have `norm` inference rows.
- `dfd_balanced_thresholds_45rows.csv`: DFD video-level balanced-threshold results.
  - 45 rows = 3 backbones x 5 seeds x 3 variants.
  - Variants are `raw`, `direction`, and `normtrain_norm`.
- `dfd_balanced_thresholds_summary.csv`: grouped threshold and balanced-accuracy summary.

## Metric Level

Main experiment claims should use the video-level CSVs in this directory.

Frame-level figures are retained separately under `figures/frame_level/`. They are visualization outputs, not the source of paper-level video AUC claims.

## Reproducibility of the `direction > raw` CDF claim

The `cdf_auc` column in `auc_video_level_60rows.csv` is the source of the
conference claim that "direction inference > raw inference on CDF"
(rawtrain checkpoints: direction − raw = +0.0142, **15/15 seed×backbone cells
direction wins**). This section documents exactly how those numbers were
computed and the boundary at which the claim stops reproducing.

### How the original numbers were computed

The CSV was generated by `scripts/eval_alpha_sweep_rawcls_normprompt.py`
(**deleted** in commit `7fb5095` "clean paper reproduction artifacts"). The
computation chain is:

```
model.extract_features -> classifier -> softmax -> per-frame prob_fake
  -> engine.run_sample_eval_epoch
  -> sample_rows_to_video_predictions (src/.../evaluation/sample_eval.py)
  -> group by video_id ONLY, take mean(prob_fake)   # <- the decisive step
  -> single pooled AUC over all videos (all fakes vs all reals)
```

So `cdf_auc` = pooled video-level AUC with video aggregation
`P_video = mean_t(prob_fake_t)`, where videos are grouped by **`video_id`
alone**.

### Reproduction check (re-computed from independent frame scores)

Re-computed from the Phase-A `per_frame_scores.parquet` (same 15 rawtrain
checkpoints, same scoring, same `mean(prob_fake)` aggregation), grouping by
`video_id` alone to match the original:

| Domain | Metric | `|original − recompute|` |
|---|---|---|
| CDF  | raw AUC      | 0.0000 |
| CDF  | direction AUC| 0.0000 |
| FF++ | raw AUC      | 0.0000 |
| FF++ | direction AUC| 0.0000 |
| CDF  | Δ (dir−raw) sign agreement | **15/15** |

The original numbers reproduce **exactly to 4 decimal places** (e.g. CLIP s7
CDF: original raw 0.7992 / dir 0.8224; recompute raw 0.7992 / dir 0.8224).

### Root cause of the discrepancy with the Phase-A re-analysis

The Phase-A diagnostic pipeline (`src/.../diagnosis/aggregation.py`,
`aggregate_frames_to_videos`) groups by **`(method_id, video_id)`**, not by
`video_id` alone. In FF++/CDF the same `video_id` (pair_id) is reused across
forgery methods — identity `000_003` is faked separately by simswap,
blendface, faceswap, etc. Grouping by `video_id` alone **merges different
methods' fakes of the same identity into one "video"**; the
`(method_id, video_id)` key keeps them separate (semantically correct). This
is flagged in `aggregation.py`:

> "Without method_id in the key, frames from different methods' videos that
> share a pair_id would be averaged together — a silent semantic bug."

The grouping key alone flips the result:

| Grouping key | CDF Δ (dir−raw) | direction wins |
|---|---|---|
| `video_id` alone (original / conference) | **+0.0142** | **15/15** |
| `(method_id, video_id)` (Phase-A, correct) | −0.0044 | 4/15 |

### Interpretation

The conference claim "direction > raw on CDF, 15/15" **is reproducible**
(matched to 0.0000 above), but it holds **only under the `video_id`-only
grouping that merges forgery methods sharing a pair_id**. Under the
semantically correct `(method_id, video_id)` grouping the direction advantage
disappears and slightly reverses (−0.004, 4/15). In other words, the effect is
a property of the video-aggregation grouping, not of the features — consistent
with the later pooling/saturation study, which shows the residual per-method
direction advantage (e.g. FSGAN) collapses to 0.0000 after temperature
calibration.
