# 下一阶段 owner 安全交接要求（准备稿，未实现）

当前结论：现运行的 D owner 无中途合作接口。维持原 owner 及原训练/缓存阶段屏障，不把本准备稿作为 H 或手动 cache 准入。原始 2020 独立 CPU 反例保留，不重做被否决的竞争尝试。精确现状与源文件哈希见 reports/D_owner_interim_handoff_capability_20261024T1150.json。

## 可复用范围

下一次原 owner 自然终态、所有子进程及内核租约释放后，才具备部署新版调度机制的技术交接点。本稿不授权修改当前冻结科学协议，也不把未来代码的通过作为本次实验资格。若未来使用新调度代码，另记代码版本、受影响的资格绑定与必要重验；现有 D/H bundle 和资格不被静默重绑。涉及H bundle变化时须保留旧probe并按同一固定416行源域协议重建身份，全部既定六项真实GPU证明仍逐项验收；CPU通过或调度通过不代替GPU资格。

## 方案边界

保留单一 owner。未来若要让已完成模型的缓存或已通过数据资格的 H 微型资格与其他训练并行，应由同一 owner 的就绪任务图决定：单模型终态及完整身份是其缓存依赖，H 科学资格和全局资源许可仍分别验证。全局只允许四个 GPU0–3 单卡任务，保护GPU4–7及其他项目；初始200GiB工作集估计+50GiB保留，生产中另核实际新增缓存/统计/临时文件，13.5674GiB纯D特征下界不得替代总预算；有效批量、优化器尝试数、精度、种子、训练选择和阈值均保持冻结值。

不采用 H-only 先抢锁再验证，也不把显存空闲、PID快照、固定等待时间或删除/改名锁文件作为准入证据。当前 owner 的 pending=[] 只是该批次没有待派发任务，不是对其他进程开放的租约。

## 实现前必须决定并复审的接口

优先研究由 owner 原子持有 GPU 租约、通过同一 open-file-description 交给子进程的方案。父端保留租约直到收到绑定 child PID/starttime、run、UUID、锁设备/inode 和代码身份的启动确认；worker不得用第二个独立 FD 重新非阻塞争抢同一租约。确认后子进程持有租约覆盖全部 CUDA 生命周期，父端关闭自己的副本；父端崩溃时已确认子进程仍持有。该方案需要同步修改未来 owner 与 worker，不能通过 H-only 补丁接入当前 owner。

另一条未来路径是单 owner 内统一任务图并允许暂时锁冲突返回到待排队状态；但必须证明 CUDA 前的无副作用和租约一致性，不能将训练内部错误吞为可重试冲突。两种方式不可在同一次生产切换中未经证明混用。

## CPU 验收要求

- 在临时路径使用真实 flock 与可控进程屏障，强制覆盖原 reserved()/Popen 间隙；未来机制在所有拒绝分支都不能导致已获许可任务失败。
- 同时提出五个任务时最多四个拥有租约；同 UUID 同时最多一个 owner/worker链；GPU4–7永不成为候选。
- 覆盖父在 spawn 前/后、确认前/后崩溃，子启动失败、确认超时、子退出、重复启动及控制请求重复送达。每个任务至多一个有效执行，失败证据保留；仅 GPU 准入冲突可回队。
- PID复用、锁文件inode更换、符号链接、过期状态、UUID变化、磁盘不足、错误 run/config/bundle 必须拒绝；拒绝不得改变现有训练/科学工件。
- 正常恢复必须逐模型/角色验证已提交工件；不能重复训练已完成模型、重复导出已验收缓存或更改 frozen-last/source-best绑定。
- 比对同种子原/新调度的尝试日志、样本/增强哈希、优化器成功与AMP跳步语义；调度通过不代表模型确定数值相等，差异须按冻结数值协议处理。

## 生产交接门槛

CPU并发/崩溃/恢复测试及独立复审通过后，在无其他项目干扰的空闲允许卡上做受控真实资格。采用严格的原子部署/回退记录；只在无旧 owner/worker、队列与GPU锁实际释放、身份及容量通过的边界启用。先有可核验工件再考虑生产接续，不能热改当前进程。本阶段只保存本准备稿，没有创建新派发器、后台任务或调度。
