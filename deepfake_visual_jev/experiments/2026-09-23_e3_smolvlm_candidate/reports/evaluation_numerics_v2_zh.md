# E3 评估数值实现修订记录

本次修订发生在正式 FF++/CDF 测试域推理之前，只依据 FF++ 源验证集进行实现诊断。训练和选模继续使用原协议；本文不是语义能力或跨域表现的验证结果。

## 失败与原因定位

使用 seed 42 第2轮正式训练检查点，SHA256 为 `c1f9211158170dd9d7e12c0e021ca593f90a53c75767b9ea0ebf513543215bed`。输入为源验证集2真+2假物理帧、train 语言池的 T1–T5，共20条请求。没有使用测试域预测。

原始 GPU 检查实际退出1：最大概率误差 `1.1324882507324219e-6`，预测一致率100%，超过冻结的 `1e-6` 门槛。首次探针在保存JSON前断言失败；后续诊断明确记录这项限制，并复现、保存了相同失败。

原 E2 换序审计先在完整混合批次计算参考分数，再按候选数量拆成子批次。E3 原实现还按批次最长提示填充，所以审计同时改变候选顺序、批大小和填充长度。

| 源域对照 | 最大概率差 |
|---|---:|
| 完全重复原批次 | 0 |
| 保持原批次，只颠倒候选顺序 | 0 |
| 不换序，只取二候选子批次 | 1.13248825e-6 |
| 各子批次内部换序 | 0 |
| 只固定填充长度为128 | 1.43051147e-6 |
| 只固定每次前向批大小为96 | 3.51667404e-6 |
| 同时固定两种尺寸 | 2.98023224e-8 |

这些控制把本次超差定位到 FP32 计算尺寸变化，不能解释为模型在这批样本上依赖候选语义顺序。这里没有进一步声称已定位具体 CUDA 内核或逐层误差来源。

## 统一的评估修订

新增 `src/evaluation/smolvlm_fixed_shape.py`，继承训练模型，保持完全相同的参数名、结构和数值精度。只改变评估时的分批与填充：

1. 每条图像/问题/候选提示依据自身长度进入128、256、512、1024之一的长度桶。
2. 每次前向固定为配置中的96条候选；不足时重复最后一条合法输入，填充行的分数被丢弃。
3. 完整语言骨干和共享标量头都使用固定尺寸；真实候选分数映射回原位置。
4. 所有11种条件、两个域和三个种子都使用这一实现；原 E2 换序审计和概率映射完全不改。

不修改正在运行的训练源码、检查点、源域选模、视觉缓存、数据切分、阈值和统计判定。没有对概率进行舍入、截断或按候选语义排序。

新旧数值路径在上述源域样本上的最大概率差为 `1.96695328e-6`，最大logit差为 `8.47876072e-6`，预测一致率100%。这个路径间差异被完整保留；它不是换序不变性结果，不能声称新旧概率逐位相同。正式评估将统一使用修订路径。
