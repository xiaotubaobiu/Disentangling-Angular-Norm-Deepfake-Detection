# 架构假设的含义与判定边界

本文写于 E3 正式训练期间，尚无 E3 目标域结果。它说明要检验什么，不提前宣布假设成立。

## 对研究猜测的修正

“保留必要的语言结构，同时约束生成与计算”是可检验的研究方向。CLIP 的文本编码器本身也是 Transformer，因此关键区别不能表述为“CLIP 不是 Transformer、语言模型才是 Transformer”。应检验的是：预训练目标、保留下来的 token 信息，以及图像—问题—候选的交互，是否足以支持本任务所需的语义关系。

CLIP 的图文对比训练主要约束整体图像和文本的匹配。句子级表示仍可包含语言语义，但不能假定它能稳定表达和运用否定、问题极性、词语组合及未见表达。E2 又把池化后的图像、问题和候选表示交给新训练的两层 decoder；这个 decoder 具有注意力结构，却没有因此自动继承语言模型的预训练能力。

这里的判断函数也要分层看：

\[
s_i=f_\theta(x,q,c_i)=w^T h_\theta(x,q,c_i)+b,
\qquad
P(c_i\mid x,q,C)=\frac{\exp s_i}{\sum_{c_j\in C}\exp s_j}.
\]

最终的标量读出可以很简单。关键是中间表示 \(h_\theta\) 是否已经包含“这个图像是否支持这个问题下的这个候选”的关系。复杂的输出头不能保证语义理解；简单的输出头也不能单独证明模型缺少语义理解。

因此，本项目更准确的目标是：**限制输出空间和计算开销，保留完成任务所需的最小语义能力。** 极性、否定和组合能力是需要保住的内容，不能把它们也一并视为应删除的“推理能力”。

## 已有结果支持什么

- H1 支持固定候选共享评分器保留真实性排序能力。三种子 CDF 视频 AUROC 为91.1267%。这不等于证明模型理解自然语言问题。
- E2 在同一冻结视觉塔上得到 CDF AUROC 82.2181%，比 H1 低8.9087个百分点；极性、未见措辞与部分控制也失败。这说明新学到的决策方案存在问题，不能说冻结的视觉权重被训练损坏。
- E2 的候选换序门槛 G3 通过，说明候选顺序不再决定类别位置。共享评分结构本身就有助于这种性质；它不足以证明否定或组合语义被正确使用。
- 现有实验同时改变决策网络、训练任务和语言分布，尚不能把全部退化归因于池化、CLIP 预训练目标、随机初始化的交互层，或其中某一个因素。

来源：H1 结果报告与 E2 的 `e2_validation_summary_zh.md`。这里的 FF++/CDF 均为 DF40 来源域切分，包含相同16种方法，不是原始官方 benchmark 或未见方法测试。

## E3 正在检验什么

第一阶段保留 SmolVLM 的预训练视觉塔、连接器和完整语言 Transformer，以完整图像 token、问题和候选上下文做共享标量评分，移除词表输出头与逐词生成。保留原有因果注意力；一次前向读取已给定的输入，不等于自回归生成答案。

先验证这一整条路线是否同时做到：真实性非劣、未见措辞迁移、问题极性一致、显式否定、候选组合，以及比长度匹配的无意义文本更好。训练和模型选择只用 FF++ 源训练/验证集。最终三个种子、两个域、11种条件，共66组；冻结门槛和10,000次配对视频 bootstrap 均在正式目标域推理前确定。

这一阶段同时更换视觉、语言和预训练交互。全部通过可支持“预训练多模态结构可以用于受限候选决策”的可行性，仍不能单独证明 E2 的失败只由语言架构造成。若失败，需要按真假排序、阈值表现和各项语义测试分别解释，不能把任何一个失败直接推广成“语言模型无效”。

按用户给定的条件顺序，第一阶段成功后，才继续 H1 CLIP 视觉塔 + SmolLM2-135M + 预训练/蒸馏 bridge + H1-preserve loss；该阶段成功后再压缩语言层。保持 H1 视觉塔的阶段能减少视觉表示变化这一混杂因素。更强的因果归因仍需要同视觉、同输入、同训练预算下的对照。

## 最终汇报不应混淆的量

- 源域五任务训练/验证准确率与固定真假任务的视频 AUROC 不是同一个指标。
- 候选 softmax 是相对于给定候选集合的概率，不自动获得真实世界校准。H1 的 CDF 排序较好，但0.5阈值下真实类召回很低；最终需同时报告 AUROC、平衡准确率、真实类召回及校准指标。
- 移除逐词生成不自动保证推理更快：目前每个候选都需要自己的语言前向，虽然共享一次图像特征提取。速度优势必须测量；现阶段可以确认的是输出被限制为候选分数，且词表输出头已经移除。
- 当前组合诊断检查含合取与否定的候选描述；它不能代表任意开放词汇候选集合上的通用推理能力。
- CPU/GPU smoke、测试通过、源域中间检查点，均是实现检查，不能代替完整 FF++/CDF 结果。
