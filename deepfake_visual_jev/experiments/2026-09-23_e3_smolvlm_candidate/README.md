# E3：预训练多模态语义与共享候选评分器

用户授权：立即完成验证并汇报结果；仅使用物理 GPU 0–3；不使用子智能体。

## 完整研究目标与执行顺序

1. SmolVLM-256M-Instruct 保留预训练视觉塔、连接器、语言 Transformer，移除词表输出头及逐 token 生成，训练 NanoJev-style 共享候选评分器，验证 E2 暴露的语义与跨域问题。
2. 第一阶段达到验证标准后，迁移到已验证的 H1 CLIP 视觉塔 + SmolLM2-135M，使用蒸馏/预训练 bridge 与 H1 能力保持约束。
3. 第二阶段成功后，压缩为更浅的语言 student，保留问题极性、否定、候选组合、未见措辞与 CDF 真假决策能力。

后两阶段具有明确前提。前阶段失败时应报告已完成证据和未触发阶段；实现完成、smoke 或少量样本不代表科学验证完成。

## 第一阶段设计

官方模型：`HuggingFaceTB/SmolVLM-256M-Instruct`，固定 revision `7e3e67edbbed1bf9888184d9df282b700a323964`。

- 使用 `AutoModel` 载入此版本实际声明的 `Idefics3Model` 多模态基座；不保留 `lm_head`，不调用 `generate`，不计算词表概率。
- 每个候选分别与同一图像、问题拼成完整上下文；全部候选共享同一个预训练基座与标量评分头。对候选分数做 softmax，交叉熵监督正确候选位置。
- 保留原语言模型的因果注意力结构和已学权重。单次候选评分使用完整输入，输出单个分数，没有自回归生成循环。
- 同一图像的视觉 token 只计算一次再供候选复用；保留 token 序列及预训练连接器。
- 视觉塔与连接器先冻结，语言模块以小学习率适配、评分头从头训练。具体批量和吞吐由只读取 FF++ 训练/验证数据的 smoke 确定，再冻结正式配置。
- 使用 H1/E2 相同 DF40 记录、16 方法、训练/验证/测试分割、帧采样和视频键。SmolVLM 使用自身图像归一化和预训练输入分辨率，属于明确的模型变化。
- 先做单种子工程 smoke；正式训练种子为 42、7、2048。模型选择仅使用 FF++ seen-language validation，测试域和未见文本不用于选模。
- 正式评估覆盖 FF++、CDF 两域及 E2 七条件；G1–G6 数值阈值沿用，另补显式否定表达和对候选组合的检查。新任务词库和任何控制修正必须在正式评估前冻结。
- H1 为真实性非劣基线，E2 为语义失败参照。报告视频 AUROC、平衡准确率、真实类召回、语义一致性、Brier/ECE 与参数/推理成本。
- E2 冻结无意义候选长度未匹配，直接复用的 G6 仅作可比结果；需要另外完成长度匹配的控制才能作语义因果解释。

成功要求：两域真实性 AUROC 相对 H1 的差值及单侧 95% 下界均不低于 -0.01；语义泛化、极性、候选排列、家族与控制满足冻结门槛；保留完整来源、三种子与配对视频 bootstrap。若部分能力恢复，按部分支持报告，不能自动判为全目标成功。

补充诊断措辞、长度匹配规则及门槛见 `configs/diagnostics.yaml`，在正式训练和测试前确定。训练与语言主协议见 `configs/candidate.yaml`。完整有效批量为 512（每卡 32，4 卡，累积 4 次）；语言学习率 1e-5，评分头 1e-4，最多 15 轮，源域 seen-language 验证 CE 连续 5 轮未改善时停止，验证使用 EMA 权重。原空间/颜色/压缩增强保留在 224 像素后，再经官方处理器转换为 512 像素、均值/标准差 0.5。

## 因果解释

SmolVLM 与 E2 同时在视觉表示、语言表示、预训练交互和适配方式上不同。成功证明预训练多模态候选决策路线可行，但不能单凭整模型比较断言 E2 失败仅由语言架构导致。原架构失效原因需由后续保持视觉塔的迁移及针对性消融进一步检验。
